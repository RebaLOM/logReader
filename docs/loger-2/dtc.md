# Диагностика DTC в LOGER 2

Функционал диагностики Локаруса из `master` (`ace31b9`) перенесён в
`codex/loger-2-workspace` с сохранением нового интерфейса и его исправлений обработки.

В карточке **«Источник данных»** доступна кнопка **«Диагностика DTC…»**.
Выберите файл или папку логов; описание CAN-посылок для диагностики не требуется.
Окно поддерживает светлую и тёмную темы, сводку SPN/FMI, интервалы наблюдения,
снимки и исходные данные. Количество ошибок, полнота списка и `Н/Д` остаются
доступны в этом окне.

В **«Параметрах экспорта»** флажок **«Добавлять DTC в результат обработки»**
выключен по умолчанию. При включении CSV/XLSX получает только шесть текстовых
колонок `DTC1…DTC6` в порядке позиций протокола. Свободные и неизвестные позиции
записываются пустыми. Количество ошибок и полнота списка в файлы не выводятся.
Отдельный отчёт не создаётся. Разрыв данных по умолчанию — 2 секунды.

Поддерживаются матричный и шаговый CSV, TRC, ASC, CANfox и пакетные режимы;
готовая выгрузка Локаруса поддерживается только при отдельном просмотре диагностики.
Подробности профиля: [DTC.md](../DTC.md).

Сохранены особенности обработки LOGER 2: запятая в дробных миллисекундах CSV,
округление времени строк ДСТ к концу периода и существующие исправления границ
блоков. Чтение состояния DTC на округлённое время строки ДСТ не изменяет часы
декодера входных кадров, поэтому допуск межкадрового времени не теряет коды
и незавершённые посылки у границы блока.

Проверки: основной набор тестов обработки, проверки интерфейса в обеих темах,
51 сценарий форматов/пакетной обработки на реальных TRC только из `DST`.
При выключенном DTC 11 контрольных выгрузок совпадают с исходной версией
LOGER 2 (`16d3feb`); для XLSX сравнивается содержимое ячеек и их типы.
Исходные TRC не изменяются, что проверяется по SHA-256.

Сборка приложения: `artifacts/loger2-dtc/app/LOGER.exe`.
Результаты тестов, сравнения и снимки окон: `artifacts/loger2-dtc/`.
