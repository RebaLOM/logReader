09.10.2026. Дополнительное требование пользователя: итоговый код должен включать все последние исправления вне UI из `bfbea81`. История этой версии: `6310fd5 → 425ff61 → ee4494c → af256cf → bfbea81`. Сам `bfbea81` меняет UI и средства его аудита; исправления ядра находятся в `ee4494c` и унаследованы последующими commits.

## Полнота переноса

Все изменения `logReader/` из этой цепочки перенесены без ручной переработки алгоритмов. **`git diff bfbea81 -- logReader` пуст**, включая проект и все 54 production `.cs`. Зависимости ядра прежние. Три изменённых файла tests также совпадают с Git blobs `bfbea81`; отдельный `CompatibilityRegressionTests.cs` сохраняет 13 случаев, добавленных при редизайне.

| Файл | Унаследованное исправление |
|---|---|
| `DstConnectBlockTracker.cs` | Запасная сетка учитывает текущий слот; Step фиксируется на конце периода |
| `TrcBlockDetector.cs` | Границы запасных блоков идут по периодической сетке, без повторного разрезания по межкадровым паузам |
| `Processing/DstConnectCsvWriter.cs` | DST `Time` сохраняет миллисекунды в `H:mm:ss.fff` |
| `Processing/TimeSeriesOutputWriter.cs` | CSV ось миллисекунд использует ru-RU десятичную запятую; clock time сохраняет свой формат |
| `ExcelLayoutBuilder.cs` | Минимальная ширина столбца «Шаг» — 12 |
| `Processing/StepOutputWriter.cs` | Минимум ширины применяется после AutoFit при XLSX сохранении |

Сохранены также функциональные сообщения статуса ошибки из `MainForm` этой версии и пояснение запасной сетки в справке. Блокировка конвертера при busy эквивалентна исходной: все browse/close кнопки блокируются. Защитный reset ComboBox из AntdUI ветки здесь не требуется; исходный выбор output format проверяется на показанной форме в обеих темах. Компоновка и production зависимости UI остаются LOGER 2.0.

Добавлены четыре унаследованных случая; один старый gap test заменён проверкой периодической сетки, DST clock assertion уточнён. Обе стороны: Release, один прогрев, пять samples, одинаковый opt-in **`--fresh-outputs`**. Перед каждым sample удаляется только предыдущий синтетический результат, вне таймера, с защитой входов и проверкой абсолютного пути. Измеряется создание нового результата; время атомарной перезаписи существующего файла этим прогоном **не измеряется**. Смешение режимов автоматически отклоняется compare script.

| Сценарий | Независимый `bfbea81` | Текущая ветка |

Managed allocations большого TRC равны: 111,17 MiB. Whole-process WorkingSet после операции — 118,33 → 135,66 MiB; для XLSX — 167,32 → 185,55 MiB. Это не изолированные пики и не удерживаемая память. Вариативность времени/WorkingSet при идентичных исходниках не даёт основания заявлять улучшение всех показателей, отсутствие leaks или отсутствие регрессий на любых данных.

Три предыдущих прогона с повторной заменой outputs остановились на `File.Replace`: «Не удается удалить заменяемый файл», на разных синтетических CSV, два раза внутри sandbox и один вне него. **Причина не установлена**; эти неполные прогоны исключены из финальной пары, алгоритмы не менялись. [Сохранённая диагностика](evidence/bfbea81/benchmark-failed-runs.md). Реальная повторная обработка в native UI и UIA проходит, atomic replacement также покрыт core tests; это не снимает ограничение указанного benchmark. Пользовательские данные не использовались.

Пара `baseline.json` / `after.json`, старые TRX и UI evidence сохранены как история ядра `6310fd5`. Ожидаемые исправления DST/CSV меняют выходные данные относительно той версии; требование равенства применяется к исправленному `bfbea81`.

## Запуск, сборка и ограничения

UI-only ReadyToRun применяется только к `LOGER.dll`. Опубликованные `logReader.dll` и сторонние DLL обязаны совпадать с обычными IL assemblies этой же сборки; это проверяет `tools/Publish-Loger.ps1`. Приложение: `artifacts/release/win-x64/LOGER.exe`, рядом нужны DLL/JSON и установленный .NET 10 Windows Desktop Runtime x64.

Для нового startup сравнения используется контролируемый baseline: прежний UI `6310fd5` с тем же исправленным ядром, что у текущей сборки. Это выделяет стоимость UI, не смешивая её с изменением алгоритмов. Новые WinForms/UIA/startup отчёты дополнительно записывают SHA-256 ядра.

Семь свежих процессов на вариант, тот же компьютер и прогретый дисковый кэш, без `LOGER_THEME` override. Startup — время от Process.Start до Windows input-idle и ненулевого HWND; это proxy готовности, не момент отрисовки каждого пикселя. Сборки, core benchmark и native UI audit во время серии не запускались.

Эти числа заменяют прежнюю серию для оценки итоговой сборки; измерения разных серий показывают вариативность среды, поэтому рост запуска не скрывается и не объявляется статистически точной универсальной величиной.
