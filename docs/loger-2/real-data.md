Зафиксированы размеры и SHA-256 **135 файлов**: 47 TRC, пять ASC, 46 CSV, один TXT, десять DBC, восемь DBF, 18 XLSX. До и после каждого полного прогона все 135 SHA-256 совпали. Исходные файлы и прежние результаты пользователя не перезаписывались; новые результаты находятся только в игнорируемых `artifacts/perf/real-*` внутри worktree. Бинарные публикации `pub` и архивы не являются входами обработки и исключены.

Каталог `LOGER` содержит реальные примеры и включён. OneDrive может ставить ReparsePoint на облачные папки; средства проверки теперь исключают только настоящие ссылки по `DirectoryInfo.LinkTarget`, сохраняя доступ к облачным папкам. Повторная инвентаризация новым harness дала те же 135 файлов и SHA-256: [проверка CANfox](evidence/real-data/current-canfox.json).

Из 36 файлов DBC/DBF/XLSX 18 загружаются как непустые описания устройств. Другие таблицы, существующие результаты и спецификации дают ноль устройств; это не объявляется ошибкой приложения или валидным описанием. Детектор классифицировал 47 TRC, пять ASC, 22 матричных CSV, два шаговых CSV и один CANfox TXT; остальные 22 CSV не распознаны как входной формат LOGER.

Подбор по ID не является независимой проверкой физических величин по документации оборудования. Время каждого одиночного вызова сохранено для диагностики, это не benchmark и не сравнение медиан.

## Обнаруженные ограничения

Все девять файлов `DST\*.trc` завершились с нулём строк и сообщением «Нет совпадающих устройств — проверьте файл посылок» **как в bfbea81, так и в опубликованном LOGER**. Сравнение не скрывает эти FAIL. По анализу кода причина соответствует варианту строк `N time Rx ID DLC ...` без `)` после номера: общий парсер выбирает ветвь TRC 2.x и ожидает тип кадра вместо `Rx`. Это вывод по формату и исходникам, а не исправленный дефект. Производственный парсер сохранён согласно требованию не менять ядро редизайном.

Пять входов остаются **NOT TESTED для полного декодирования**: CANfox `LOGER\педаль газа и ручка газа 0CF00300.txt`, `TrcLogs\L450E_Can4_ElMotTrsmCtrl_Diag.trc`, `pdu A1-10 reset copy.trc`, `pdu A1-10 reset.trc`, `pdu1.trc`. В предоставленных непустых описаниях не найдено соответствие выборке CAN-ID. Повтор CANfox с распознаванием ID без ведущих нулей также не нашёл описание. Подмена описания синтетическими сигналами не использовалась.

## xUnit и настоящее окно LOGER

С `LOGER_TEST_DATA_ROOT` все **137/137 tests PASS**, 0 fail / 0 skip, [TRX](test-results/real-fixtures/real-fixtures.trx). Два прежних условных теста действительно выполняют проверки: первые временные метки 22 матричных CSV и заданный период 20 ms в 38 TRC, до 5000 разобранных кадров на файл. Девять TRC из DST не проходят минимальный порог 200 кадров и в этот тест периода не входят; их ошибка явно проверена полным pipeline выше. Точного старого Downloads-файла с ожидаемыми 257 ms в наборе нет; соответствующий тест теперь сравнивает реальные первые временные метки с независимым `TimeSpan.Parse`, не приписывая всем примерам 257 ms. При неверном или пустом наборе явно заданной папки тесты падают вместо условного успеха.

Через Windows UI Automation запущен отдельный опубликованный LOGER.exe, **7/7 checks PASS в каждой теме**: навигация, смена/сохранение темы, ввод реальных TRC и DBF, обработка, повторная запись результата и сохранность источников. [Dark](evidence/real-data/uia-dark.json), [Light](evidence/real-data/uia-light.json). Файл `L450E_ElTrsmMot_RecupBrk_T1.trc` + `dbf examples\L450E_CanLogger.dbf` даёт 2014 строк и тот же CSV SHA-256, что прямой вызов опубликованного ядра. Проверка повторной записи ждёт нового времени изменения файла и успешного завершения. Успех этого конкретного повторения не устанавливает причину прежнего сбоя стрессового `File.Replace` benchmark.

SHA-256 опубликованного ядра: `4061AA5A23CC398A0464B22D17ECF635F6FE2D9CC4739928A615E3746EF49B78`; UI DLL: `2C85D7101B59E537A46C2155B805FBB72D30541D52358296AC706FDE3FD55C5D`. Артефакт не пересобирался из-за изменений тестов. Для каждой загрузки/обработки JSON сохраняет первые 30 сообщений и число опущенных `MessagesOmitted`; полные исходные журналы прогона сохранены локально в игнорируемых `artifacts/real-data-audit/raw`. Статусы, входные и выходные hashes, количество строк и ошибки не сокращены. Остальные ограничения UI/DPI/performance из [итогового отчёта](report.md) сохраняются.
