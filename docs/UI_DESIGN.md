# LOGER — визуальная система и проверка интерфейса

## Аудит исходного интерфейса

Исследованы все 14 форм, встроенный выбор источника логов, CAN payload UserControl,
Designer-файлы, ресурсы, обработчики, динамические панели, таблицы и пакеты.
Основные проблемы: одинаковая важность кнопок, плотные блоки без заголовков,
фиксированные координаты и размеры, неодинаковые поля и таблицы, красно-зелёные
переключатели, отсутствие явных пустых/загрузочных состояний, постоянное создание
панелей статистики при изменении размера и модальные сообщения об обычном сохранении.

## Концепция

Светлый Fluent-подобный интерфейс: нейтральная рабочая область, белые поверхности,
тонкие границы, синий акцент для основного действия, линейные иконки и читаемая
типографика. Отдельные тёмные цвета пока не включены: светлая тема доведена до
общей системы без смешивания неполных тем и стандартных тёмных popup-окон.

| Роль | Токен |
| --- | --- |
| Рабочая область / поверхность / вторичная поверхность | `Background` / `Surface` / `SurfaceSecondary` |
| Граница / активная граница | `Border` / `BorderHover` |
| Основное действие и его состояния | `Primary` / `PrimaryHover` / `PrimaryPressed` / `PrimarySoft` |
| Текст | `TextPrimary` / `TextSecondary` / `TextMuted` |
| Результат и проблемы | `Success` / `Warning` / `Error` / `Info` и мягкие фоны |
| Битовая карта | централизованный `PayloadColors`, сохранено соответствие сигналов цветам |

Палитра находится в `logReader.UI/Theme/AppTheme.cs`. Шрифты задаются в
`Typography.cs`: Segoe UI Variable Text при наличии, иначе Segoe UI; отдельные
роли заголовков, основного/вторичного текста, подписей и моноширинных CAN ID.
Базовая сетка: 4 / 8 / 12 / 16 / 20 / 24 / 32; радиусы 6 / 8 / 12.
Логические размеры задаются при 96 DPI; рисуемые векторы и payload масштабируются
через `UiScale.Px` ровно в месте рисования.

## Компоненты и структура

- `Controls/`: кнопки Primary/Secondary/Ghost/Danger с hover/pressed/focus/disabled,
  карточки, навигация, поля с общей оболочкой, статус, уведомления, пустые состояния,
  вкладки и единый диалог подтверждения. Нативные ввод, dropdown, spinner,
  клавиатура и доступность сохранены.
- `Icons/`: векторные пути Lucide, 24×24, stroke 2 с округлыми окончаниями;
  исходный commit и полные ISC/MIT уведомления находятся рядом с кодом.
- `Helpers/WindowSizing.cs`: ограничения окна по рабочей области активного монитора
  после начального DPI-масштабирования и при смене монитора.
- `MainForm.Layout.cs`: композиция рабочей области отдельно от обработки файлов.

Главная навигация: «Обработка», «Библиотеки», «Инструменты», отдельная справка.
Обработка состоит из шагов «Источник», «Правила декодирования», «Результат»
и необязательных составных параметров. Карточки переходят из двух колонок в одну
при уменьшении доступной ширины. Основное действие и статус остаются внизу;
журнал имеет изменяемую высоту, копирование, очистку и пустое состояние.

Редакторы разделяют метаданные, фильтры, таблицы и карту битов. Контекстные действия
доступны только при выбранной строке. Таблицы используют горизонтальные разделители,
спокойное выделение, hover и сообщения при отсутствии данных. Фильтрация сохраняет
индексы исходных моделей. В составном редакторе изменения остаются в памяти до
«Сохранить изменения»; при закрытии можно сохранить, отказаться от правок или
отменить закрытие. Редактирование отдельной посылки применяет данные в родительский редактор,
который затем сохраняет файл — интерфейс объясняет эту разницу.

Диалоги параметров показывают положение/размер сигнала, физическое преобразование
и карту payload в отдельных секциях. Валидация указывает поле/ячейку. Сохранено
кодирование Intel/Motorola, NUM/BIN, границы raw/physical, trigger и порядок фрагментов.
Исправлены только ошибки UI: устаревшее выделение при смене endian, Enter в карте,
инициализация BIN вне уменьшенного DLC, раннее DPI-масштабирование и обновление
доступности кнопки после `ItemCheck`.

Просмотр логов считает кадры общими парсерами библиотеки в фоне, показывает загрузку
и виртуальную таблицу, прекращает чтение при закрытии окна. Чтение CAN FD из нового
движка сохранено; редакторы сохраняют ограничение CAN FD, предотвращающее потерю
данных при записи. Выбор устройств и параметров применяет снимок фильтров только
по OK; отмена сохраняет прежние фильтры. Справка сохраняет дерево тем,
поиск и выделение совпадений. Ошибки/подтверждения оформлены общим диалогом;
выбор файлов и папок использует нативные Windows-диалоги.

| Форма | Новая композиция |
| --- | --- |
| `MainForm` | Навигация, карточки шагов, закреплённое основное действие и журнал. |

| `CompositeParamEditForm` | Параметр, упорядоченные фрагменты, преобразование и карта битов. |

Встроенный выбор источника и общий `AppDialog` оформлены той же системой.

## Проверка

Редизайн объединён с `master` на коммите `3dfa8a5` (backend audit fixes).
Новые API обработки, прогресс, отмена, атомарная запись, снимки фильтров,
кэширование описаний и защита редакторов перенесены в новое оформление.
Результат определяется по `ProcessingResult` / `BatchOutcome`, а не наличию
предыдущего файла. Исправлена гонка закрытия: если операция заканчивается,
пока открыт вопрос о прерывании, положительный ответ всё равно закрывает окно.

На Linux доступны компиляция WinForms и существующие тесты библиотеки:

```bash
dotnet build logReader.slnx -c Release -p:EnableWindowsTargeting=true
dotnet test logReader.Tests/logReader.Tests.csproj -c Release --no-build
```

WinForms-тесты работают на Windows и включены в Windows job CI:

```powershell
dotnet test logReader.UI.Tests/logReader.UI.Tests.csproj -c Release
dotnet run --project logReader.UI/logReader.UI.csproj -c Release
```

Linux не исполняет Windows Desktop runtime. Компиляция не подтверждает отображение
контролов на экране; автоматические UI-тесты также не заменяют визуальную проверку.

После объединения с актуальной `master` набор библиотеки сообщил 104 успешных теста;
два из них выходят досрочно без личных файлов-фикстур, которых в облачной среде нет.
Исходники обработки и её тестов относительно новой `master` не изменены. Добавлены
38 Windows UI-сценариев: загрузка всех
форм, доступность действий при уменьшении окон, навигация, подтверждения,
конвертация, выбор параметров, карта битов, прогресс/отмена и закрытие во время
завершения фоновой операции. Они скомпилированы и включены в CI,
но в этой Linux-сессии не запускались.

### Приёмка на Windows

1. Открыть главное окно и все редакторы/диалоги; пройти навигацию, выбрать файлы,
   создать XLSX/DBC/DBF и составные параметры, применить и отменить изменения.
2. Проверить 100 / 125 / 150 / 175 / 200%, Full HD / 2K / 4K и перенос между
   мониторами. Окна должны помещаться в рабочую область; содержимое прокручивается,
   основные действия доступны, текст и поля не перекрываются.
3. Проверить минимальные размеры, длинные пути, имена сигналов и ошибки. Проверить
   отсутствие серых углов на белых карточках и читаемость disabled/focus.
4. Пройти Tab/Shift+Tab, Enter/Escape, Ctrl+F; клавиатурное выделение и drag в карте
   Intel/Motorola должны совпадать с выбранным сигналом. Проверить BIN вне DLC.
5. Проверить пустые таблицы, отсутствие совпадений, чтение большого лога,
   закрытие просмотра во время чтения, запрет повторной записи, отмену обработки и
   безопасное закрытие после очистки временных файлов, успех и ошибку. Полная ошибка остаётся в журнале; resize сохраняет
   состояние результата.
6. Проверить выбор/отключение устройств, включая скрытые поиском, сверку ID,
   CSV/TRC/ASC/CANfox, объединение/разбивку по датам и ДСТ Коннект. Сравнить выходные
   файлы с прежней версией на тех же входных данных.
7. Проверить dirty-close: «Сохранить» / «Не сохранять» / «Отмена», подтверждение
   удаления, откат при ошибке записи и справку с поиском/примерами.

Необходима отдельная визуальная приёмка на Windows. Скриншоты и проверка физических
DPI в Linux не выполнялись.
