# Проверка DTC на файлах

Инструмент создаёт синтетические логи пяти CAN-форматов и проверяет обычные CSV/XLSX и CSV ДСТ, фиксированные текстовые колонки, общий сервис диагностики и три режима пакетной обработки. Реальные DTC-логи читаются **только непосредственно из каталога второго аргумента**: `*.trc`, без поиска в соседних каталогах. `LocarusOutp` не используется. Файл посылок можно указать отдельно через `--dbc`; он служит только описанием числовых параметров. Результаты создаются только в первом аргументе; контрольные суммы исходников проверяются до и после запуска.

```powershell
dotnet run --project tools/Loger.DtcAudit -c Release -- artifacts/dtc-recheck/audit C:/Users/Re/OneDrive/Desktop/DST_LOGER/DST
```

JSON `audit.json` содержит статусы проверок и контрольные суммы. Для сравнения с исходным ядром запустите ту же сборку инструмента с прежним `logReader.dll`, аргументами `artifacts/dtc/baseline - --baseline`, затем сравните `Hash` записей с одинаковым `Key`. Для CSV сравниваются байты SHA-256; для XLSX — адреса, типы и значения ячеек, поскольку метаданные ZIP могут отличаться между сохранениями.

Этот исторический on/off-аудит явно отключает автоматический режим и выбирает полную запись SPN/FMI, чтобы результаты оставались сравнимыми с прежними версиями. Компактный формат и автоматическое добавление по умолчанию проверяются в `DtcDisplaySettingsTests`.

Автоматические тесты решения читают реальные TRC, если `LOGER_DTC_TEST_DATA_DIR` указывает непосредственно на `DST_LOGER/DST`. Для указанного `trace_…085033.trc` проверяются 1038 полных циклов без активных кодов; для `контрвращение_085008.trc` — 15 полных циклов с SPN 32770 / FMI 0. GUI-тестам Windows нужен доступ к рабочему столу.
